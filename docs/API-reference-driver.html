TheRide — Driver API Reference

Base URL: http://localhost:3000/api/v1  ·  Auth: Authorization: Bearer <token>  ·  Content types: JSON (auth, vehicle) and multipart/form-data (documents, photos)  ·  Version: Nov 14, 2026

Driver journey order

Register → Verify email → Login → Onboarding-status (drives every screen)
→ Upload documents → Admin review → [Rejected? Re-upload] → Add vehicle
→ Dashboard → Trips / Wallet / Earnings / Ratings

GET /auth/onboarding-status — nextStep values for drivers:

nextStepMeaning
VERIFY_EMAILEnter the emailed code
UPLOAD_DOCUMENTSShow document upload screen
AWAIT_VERIFICATIONAdmin is reviewing — show "under review"
REUPLOAD_DOCUMENTSDocuments rejected — show upload screen again
ADD_VEHICLEApproved, but no APPROVED vehicle yet
DASHBOARDGo to dashboard
The old COMPLETE_PROFILE step no longer exists for drivers — that screen was removed from the design. License details come from the uploaded license image.

1. Auth

POST/auth/register

{
  "fullName": "Ugo Obi",              // or firstName + lastName
  "email": "ugo@example.com",
  "phoneNumber": "08031234567",        // REQUIRED for driver
  "password": "Passw0rd!",
  "confirmPassword": "Passw0rd!",
  "role": "DRIVER"
}
{
  "success": true,
  "message": "Registration successful. Please verify your email.",
  "email": "ugo@example.com",
  "role": "DRIVER",
  "driverId": "DRV-482913",
  "firstName": "Ugo",
  "lastName": "Obi"
}
  • 201 on success · 409 email/phone exists · 422 validation (weak password, invalid Nigerian phone).
  • Password: min 8 chars, uppercase + lowercase + number + special character.

POST/otp/verify-email

{ "email": "ugo@example.com", "code": "4821" }
{ "success": true, "message": "Email verified successfully." }

Resend: POST /otp/resend-email { "email": "…" }.

POST/auth/forgot-password

{ "email": "ugo@example.com" }
{ "success": true, "message": "If the email exists, a reset code has been sent." }
Drivers receive the 4-digit code only (10 min, no web link). Corporate/platform admins receive the web link only.

POST/auth/verify-reset-code

{ "email": "ugo@example.com", "code": "1550" }
{
  "success": true,
  "message": "Reset code verified.",
  "data": { "resetToken": "9f2c8d1e4b…" }
}
  • Hold the resetToken in app memory — the next request needs it.
  • 400 invalid/expired code. The code is consumed here and cannot be reused.

POST/auth/reset-password/:resetToken

{ "newPassword": "N3wPassw0rd!", "confirmPassword": "N3wPassw0rd!" }
{ "success": true, "message": "Password has been reset successfully." }

PATCH/auth/change-password 🔐 token

{ "currentPassword": "Passw0rd!", "newPassword": "N3wPassw0rd!" }
{ "success": true, "message": "Password changed successfully." }

POST/auth/logout 🔐 token

{ "success": true, "message": "Logged out successfully." }

2. Driver documents — multipart/form-data

POST/driver-documents 🔐 DRIVER

form-data fieldTypeRequired
driverLicensefile✅
vehicleRegistrationfile✅
insuranceCertificatefile✅
selfiefile✅
nationalIdfileoptional
fullNametextoptional — fallback name if OCR unavailable; names auto-populate from the license image
{
  "success": true,
  "message": "Driver documents uploaded successfully.",
  "data": {
    "id": "b31a…",
    "driverId": "8d2e…",
    "driverLicenseUrl": "https://res.cloudinary.com/…/license.jpg",
    "vehicleRegistrationUrl": "https://res.cloudinary.com/…/registration.jpg",
    "insuranceCertificateUrl": "https://res.cloudinary.com/…/insurance.jpg",
    "selfieUrl": "https://res.cloudinary.com/…/selfie.jpg",
    "nationalIdUrl": null,
    "verificationStatus": "PENDING",
    "verificationNote": null,
    "verifiedAt": null,
    "extractedName": "UGO OBI OBI"
  }
}

400 — Missing documents: driverLicense — kindly upload clear and accepted files

GET/driver-documents 🔐 DRIVER

200 — same data shape as above (without extractedName); 404 if none uploaded yet.

PATCH/driver-documents 🔐 DRIVER — re-upload after rejection

form-data: at least one of the file fields above.

{
  "success": true,
  "message": "Driver documents updated successfully.",
  "data": { "…": "…", "verificationStatus": "PENDING" }
}
Status auto-resets to PENDING for fresh admin review. 400 if no file provided.
