TheRide — Platform Admin API Reference

Base URL: http://localhost:3000/api/v1  ·  Auth: Authorization: Bearer <token> (PLATFORM_ADMIN only)  ·  Version: Nov 14, 2026
Every endpoint below requires a PLATFORM_ADMIN token. Admin accounts are created with scripts/createPlatformAdmin.js. Login uses the standard POST /auth/login. Password reset for admins uses the web link email (same as corporate).

Review decision body (shared)

All review endpoints take the same PATCH body:

{
  "status": "APPROVED",      // APPROVED | REJECTED — required
  "reason": "optional note shown to the user on rejection"
}

2. Driver review

EndpointNotes
GET /admin/driversAll driver profiles (with document status)
GET /admin/drivers/:driverIdDriver detail — documents, vehicle, wallet
PATCH /admin/drivers/:driverProfileIdDecision body above
The driver decision syncs everything at once: DriverDocument.verificationStatus, DriverProfile.verificationStatus, User.isVerified, and sends the driver a notification. Rejected drivers re-upload via PATCH /driver-documents, which resets status to PENDING.

3. Passenger review

  • GET /admin/passengers
  • GET /admin/passengers/:passengerId
  • PATCH /admin/passengers/:passengerId — decision body

4. Vehicle review

  • GET /admin/vehicles — all vehicles for review
  • GET /admin/vehicles/:id
  • PATCH /admin/vehicles/:id — decision body
A driver cannot reach the dashboard step (ADD_VEHICLE in onboarding-status) until at least one vehicle is APPROVED.

5. Inspection review

  • GET /admin/inspections
  • GET /admin/inspections/:id
  • PATCH /admin/inspections/:id — { "status": "PASSED" | "FAILED", "reviewNote": "…" }
Inspection photo URLs are Cloudinary links. Driver User details inside review responses exclude password/reset-token fields.

6. Corporate review

  • GET /admin/corporates
  • GET /admin/corporates/:corporateId — profile + documents
  • PATCH /admin/corporates/:corporateId — decision body
